# 에이전트 보안과 사람 승인

에이전트에게 줄 권한, 외부 콘텐츠를 다루는 방법, 어떤 행동에 사람 승인을 거칠지 정한다.

## 코드에서 먼저 확인할 것
- 한 세션 안에 세 가지가 함께 열려 있는가: 민감한 데이터 접근, 신뢰할 수 없는 외부 콘텐츠 읽기(웹, 외부인이 쓴 이슈·메일), 밖으로 보내거나 상태를 바꾸는 실행
- 권한 검사가 프롬프트 문장에 있는가, 도구 실행 코드에 있는가
- 외부 콘텐츠가 지시문과 구분되어 들어가는가
- 출력·산출물에 비밀 값이 섞일 수 있는 경로
- 승인 요청이 얼마나 자주 뜨는가. 잦으면 사람이 읽지 않고 누른다

## 판단 기준
- **세 가지 분리:** 민감 데이터, 외부 콘텐츠, 외부 실행이 한 세션에 모이면 하나를 빼거나 그 사이에 승인 게이트를 둔다. 지키는 것: 기밀성
- **권한 강제 위치:** 보안은 도구 실행 엔진의 결정적 검사(경로 허용 목록, 네트워크 정책, 역할 권한)에 둔다. 프롬프트의 지시는 보조로만 본다
- **승인 단계:** 위험 = 실패 확률 × 되돌리는 비용. 읽기와 샌드박스 안 실행은 자동. 작업 폴더 안 수정처럼 되돌릴 수 있는 변경은 실행하고 diff와 되돌리는 방법을 보인다. 외부 전송, 운영 반영, 과금, 샌드박스 밖 변경은 미리 보여 주고 승인받는다. 지키는 것: 복구 가능성, 승인 피로 감소
- **외부 콘텐츠:** 구분자로 감싸 데이터로 표시하고, 그 내용에서 나온 외부 실행은 승인 게이트를 거친다
- **출력 검사:** 밖으로 나가는 응답·파일은 비밀 값 패턴으로 검사한다

## 과설계 신호
- 읽기 전용 에이전트의 모든 호출에 승인을 붙인다
- 외부 콘텐츠를 읽지 않는 내부 도구에 인젝션 탐지 모델부터 붙인다

## 지킬 장치
- 인젝션 시나리오 eval: 외부 문서에 숨긴 지시가 외부 전송을 시도하면 승인 게이트에서 멈추는지
- 도구 권한 테스트: 허용 목록 밖 경로·도메인 호출이 거부되는지
