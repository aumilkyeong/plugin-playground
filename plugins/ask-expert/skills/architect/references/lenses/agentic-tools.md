# 도구 인터페이스와 실행 환경

에이전트가 쓸 도구의 모양, 도구를 MCP 서버로 뺄지, 코드 실행을 어디까지 격리할지 정한다.

## 코드에서 먼저 확인할 것
- 도구 이름·인자·설명만 보고 용도를 알 수 있는가
- 실패할 때 돌려주는 메시지가 다음 행동을 알려 주는가
- 도구 출력에 크기 상한과 잘림 표시가 있는가
- 도구가 몇 개이고, 모두 매번 컨텍스트에 실리는가
- 셸·코드 실행이 있다면 파일·네트워크·시간 제한이 어디서 걸리는가

## 판단 기준
- **도구 크기:** 에이전트가 늘 묶어 쓰는 저수준 호출 여러 개는 의도 단위 도구 하나로 합친다. 서로 다른 의도는 이름부터 다른 도구로 둔다. 지키는 것: 호출 정확도, 턴 수
- **인자 모양:** 대상은 줄 번호·오프셋 계산 대신 문자열 일치나 식별자로 지정한다. 응답에는 다음 호출에 쓸 식별자를 담는다
- **실패 메시지:** 무엇이 틀렸고 다음에 어떻게 부르면 되는지 쓴다. 에이전트가 다음 턴에 스스로 고친다
- **MCP 서버 대 앱 안 도구:** 여러 에이전트·클라이언트가 같은 외부 시스템을 쓰면 MCP 서버로 분리한다. 한 앱에서만 쓰는 작은 기능은 앱 안 함수 도구
- **도구가 많을 때:** 이름과 요약만 먼저 보이고 쓰기 직전에 스키마를 읽게 한다
- **실행 격리:** 코드·셸 실행은 작업 폴더 안 쓰기, 네트워크 기본 차단, 시간·자원 상한을 OS 수준 샌드박스에서 강제한다. 밖으로 나가야 하는 일만 떼어 승인을 받는다. 지키는 것: 보안, 복구 가능성

## 과설계 신호
- 함수 하나로 될 기능을 MCP 서버와 별도 배포로 만든다
- 에이전트가 하나뿐인데 에이전트 간 통신 프로토콜을 도입한다
- 읽기 전용 도구만 쓰는데 VM 수준 격리부터 만든다

## 지킬 장치
- 도구별 eval: 대표 작업에서 잘못 고른 도구·인자 오류 비율
- 읽기 도구의 출력 상한을 테스트로 검사한다
