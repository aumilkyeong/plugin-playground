# 지식 넣기: 검색과 파인튜닝

모델이 모르는 지식을 컨텍스트로 넣을지(검색, RAG), 모델을 다시 학습시킬지, 검색을 어떻게 짤지 정한다.

## 코드에서 먼저 확인할 것
- 지식이 얼마나 자주 바뀌고, 사용자마다 볼 수 있는 범위가 다른가
- 답에 출처를 달아야 하는가
- 자료 양: 컨텍스트에 통째로 들어가는가, 검색이 필요한가
- 질문이 정확한 식별자(코드 이름, 오류 코드)를 찾는가, 뜻이 비슷한 것을 찾는가
- 원본이 바뀔 때 인덱스를 갱신하는 경로

## 판단 기준
- **검색 대 파인튜닝:** 바뀌는 사실, 권한마다 다른 자료, 출처가 필요한 지식은 검색해서 컨텍스트로 넣는다. 파인튜닝은 행동(출력 형식, 고유 문법, 작은 모델로 비용 줄이기)을 바꿀 때 쓴다. 지키는 것: 신선도, 추적 가능성
- **통째로 넣기:** 자료가 작아 컨텍스트에 들어가면 검색 파이프라인 대신 그대로 넣고 프롬프트 캐싱을 쓴다
- **검색 방식:** 식별자·키워드 질의가 많으면 어휘 검색(BM25)을, 뜻 중심 질의는 벡터 검색을 쓴다. 둘이 섞이면 결과를 합치고 재정렬한다
- **잘라 넣기:** 문서 구조(제목, 함수, 표) 단위로 자르고, 조각마다 원문 안의 위치·맥락을 짧게 붙인다
- **권한:** 권한 필터는 검색 단계에 둬서 모델이 읽기 전에 거른다. 지키는 것: 기밀성
- **한 번 검색 대 반복 탐색:** 질문 하나가 문서 하나로 풀리면 한 번 검색. 여러 문서를 이어야 하면 에이전트가 질의를 나눠 다시 검색하게 한다

## 과설계 신호
- 문서 수십 개에 벡터 DB, 지식 그래프, 재정렬 모델을 모두 붙인다
- 지식을 넣으려고 파인튜닝을 계획한다

## 지킬 장치
- 질문과 정답 문서 쌍으로 검색 적중률 eval을 둔다
- 권한 테스트: 권한 없는 사용자의 질의 결과 후보에 제한 문서 조각이 없는지
