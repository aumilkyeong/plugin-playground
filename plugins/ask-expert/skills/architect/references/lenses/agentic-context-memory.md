# 컨텍스트와 메모리

모델에 무엇을 언제 넣고, 무엇을 밖에 두었다가 꺼내 쓰고, 길어진 대화를 어떻게 줄일지 정한다.

## 코드에서 먼저 확인할 것
- 매 호출에 고정으로 들어가는 것(시스템 프롬프트, 도구 정의, 규칙)과 그 크기
- 문서·파일을 미리 다 넣는가, 목록만 주고 필요할 때 읽게 하는가
- 도구 결과가 크기 제한 없이 그대로 쌓이는가
- 세션을 넘어 남겨야 하는 것이 있는가: 사용자 선호, 지난 결정, 검증된 절차
- 대화가 길어질 때 압축·요약·새 세션 시작 처리가 있는가

## 판단 기준
- **미리 넣기 대 필요할 때 읽기:** 매번 쓰는 작은 규칙은 고정으로 넣는다. 가끔 쓰거나 큰 자료는 경로와 한 줄 요약만 주고 도구로 읽게 한다. 지키는 것: 주의 집중, 비용
- **메모리 종류별 자리:** 지금 작업 상태(계획, 할 일)는 컨텍스트 안. 지난 실행 기록은 파일로 두고 검색한다. 사실 지식(용어, 규칙, 선호)은 문서나 저장소. 절차는 skill처럼 필요할 때 읽는 파일. 지키는 것: 신호 대 잡음비
- **압축 대 격리:** 오래된 도구 출력이 쌓여 흐려지면 요약하거나 참조로 바꾼다. 큰 탐색 하나가 컨텍스트를 덮으면 서브에이전트에 맡기고 요약만 받는다
- **에이전트가 쓰는 메모리:** 쓰는 규칙과 함께 고치고 지우는 규칙을 정해서 사실이 최신으로 남게 한다. 지키는 것: 정확성

## 과설계 신호
- 문서 몇 개면 되는데 벡터 DB와 메모리 계층을 먼저 만든다
- 컨텍스트 창이 크다는 이유로 자료를 전부 넣는다
- 세션 하나로 끝나는 기능에 장기 메모리를 붙인다

## 지킬 장치
- 고정 앞부분의 토큰 수 예산을 테스트로 검사한다
- 읽기 도구 출력에 줄·바이트 상한 기본값을 둔다
