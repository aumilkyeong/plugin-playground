# AI 기능의 화면과 에이전트가 고치기 쉬운 코드베이스

느리고 결과가 매번 다른 AI 응답을 화면에 담는 구조, 에이전트가 되돌리기 어려운 일을 하기 전의 확인 단계, 코딩 에이전트가 정확히 고칠 수 있는 저장소 구조를 정한다.

## 코드에서 먼저 확인할 것
- AI 응답을 한 번에 받는지 흘려받는지(스트리밍). 중간에 끊기거나 형식이 깨진 조각을 어떻게 처리하는지.
- 응답 대기 중 화면: 진행 표시, 취소, 레이아웃 밀림.
- AI가 결제·삭제·외부 전송 같은 일을 할 수 있는지, 그 전에 사용자가 미리 보고 승인·취소할 단계가 있는지.
- 에이전트가 읽는 안내(`AGENTS.md`, 가이드)와 한 줄 검증 명령이 있는지, 디렉터리 규약이 일관된지.

## 판단 기준
- **스트리밍:** 응답이 몇 초 넘게 걸리고 앞부분만으로 쓸모가 있으면 흘려서 그리고, 전체가 있어야 의미가 있으면(구조화된 결과) 진행 표시 후 한 번에 그린다. 지키는 것: 체감 지연.
- **구조화된 출력:** 응답으로 화면 부품을 그려야 하면 스키마를 정해 검증한 뒤 그리고, 검증 실패 때의 대체 화면을 둔다. 지키는 것: 정확성.
- **낙관적 반영:** 실패가 드물고 되돌리기 쉬운 동작이면 결과를 먼저 보이고 실패 시 되돌린다. 실패가 잦거나 되돌릴 수 없으면 확인 뒤 반영한다. 지키는 것: 반응성 대비 정확성.
- **사람 확인:** 되돌릴 수 없거나 밖으로 나가는 동작은 실행 전에 차이(diff)나 미리보기와 승인 단계를 둔다. 지키는 것: 안전.
- **에이전트 친화 저장소:** 같은 일은 같은 자리·같은 모양으로 하게 규약을 두고, 에이전트가 고친 직후 스스로 돌릴 검증 명령을 하나로 묶는다. 지키는 것: 에이전트 작업의 정확성.

## 과설계 신호
- 결과가 짧고 빠른데 스트리밍 파서와 생성형 UI 프레임워크를 들인다.
- 사람이 매번 보는 단순 기능에 다단계 승인 상태 머신을 만든다.

## 지킬 장치
- AI 응답 스키마 검증 실패를 기록하고 비율에 경보를 건다.
- 되돌릴 수 없는 동작을 부르는 코드 경로에 승인 단계가 있는지 테스트로 확인한다.
