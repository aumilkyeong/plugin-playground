설계 문서에 심어 둔 위험은 여섯 가지다.
1. 크기를 정하지 않은 3MB 히어로 이미지(느린 첫 표시, 화면 밀림)
2. `<div onClick>` 결제 버튼(키보드·스크린 리더로 누를 수 없음)
3. `localStorage`의 액세스 토큰(XSS가 나면 토큰을 빼앗김)
4. 서버 HTML을 `dangerouslySetInnerHTML`로 그림(XSS)
5. 화면을 막는 동기 외부 스크립트(느린 첫 표시, 외부 장애가 화면 전체를 막음, 서드파티 신뢰)
6. 오류 화면 없이 예외를 던짐(결제 실패 시 빈 화면, 중복 결제 위험)

PASS if 응답이 이 가운데 다섯 가지 이상을 짚고, 위험을 "필수 수정"과 "확인 필요"(또는 그에 해당하는 두 단계)로 나누며, 항목마다 번호를 붙인다.
FAIL if 넷 이하만 짚었거나, 단계 구분이나 번호가 없다.
