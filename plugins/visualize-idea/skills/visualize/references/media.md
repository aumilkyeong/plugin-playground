# 매체별로 그리고 확인하기 (1.4, 9.1~9.4)

## 매체 고르기

사용자가 매체를 정하면 그것을 쓴다. 정하지 않으면 그림이 놓일 곳으로 고른다.

| 그림이 놓일 곳 | 매체 | 이유 |
|---|---|---|
| 저장소 문서(README, `docs/*.md`) 안 | Mermaid 코드 블록 | GitHub와 대부분의 에디터에서 그림으로 보이고, 글처럼 고치기 쉽다 |
| 따로 열어 볼 그림, 남에게 보낼 그림 | SVG 파일 | 브라우저에서 바로 열리고 배치를 마음대로 정할 수 있다 |
| 아티팩트 페이지 | 인라인 SVG 또는 Mermaid | 아티팩트는 Mermaid를 그대로 그린다. 배치를 정해야 하면 인라인 SVG |
| 채팅 답변 속 짧은 그림 | 터미널 텍스트 도식 | 터미널은 Mermaid를 그림으로 그리지 않는다 |

움직이는 그림(animated SVG)은 사용자가 요청할 때만 만든다. 같은 내용이면 정지 그림이 대개 더 낫다.

파일로 만들 그림의 위치를 사용자가 정하지 않으면 관련 문서 옆이나 `docs/`에 두고 경로를 알린다.

## Mermaid

- 방향은 단계가 다섯 개 이하면 `flowchart LR`, 더 많거나 휴대폰에서 볼 그림이면 `flowchart TB`.
- 레이블에 괄호, 쉼표, 따옴표, `<`, `:`가 있으면 큰따옴표로 감싼다: `A["요청 (HTTP)"]`. 줄바꿈은 `<br>`.
- 화살표 레이블: `A -->|쓴다| B`. 점선 `-.->`는 선택적이거나 추정인 관계, 굵은 선 `==>`는 강조할 길 하나에만 쓴다.
- 묶음: `subgraph 이름` … `end`.
- 강조는 채우기 색 대신 테두리로 한다. 채우기 색은 GitHub의 밝은·어두운 테마 가운데 한쪽에서 글자를 가린다.
  ```
  classDef key stroke:#C2410C,stroke-width:2px
  class B key
  ```
- 판단은 마름모 `B{"승인?"}`, 데이터 저장소는 원통 `D[("주문 DB")]`.
- 표준 다이어그램: 시퀀스 `sequenceDiagram`, 상태 `stateDiagram-v2`, 타임라인 `timeline`, 간트 `gantt`, ERD `erDiagram`. 마인드맵 `mindmap`은 위계만 있을 때만 쓴다.
- 노드가 열두 개를 넘으면 그림을 나눌지 먼저 생각한다.
- 문서에 넣기 전에 코드를 `.mmd` 파일로 저장해 렌더한다. 문법 오류가 있으면 GitHub에서 그림 대신 오류가 보인다.

## SVG 파일

- 크기는 `viewBox`로 정하고 좌표를 8이나 10 단위 격자에 맞춘다.
- 파일로 열면 페이지 배경이 없으므로 배경 사각형을 직접 칠한다. 밝은 값을 기본으로 두고, 파일 안 `<style>`의 `@media (prefers-color-scheme: dark)`에서 배경, 글자, 선 색을 바꾼다.
- 글꼴은 한글 글꼴을 앞에 둔다: `font-family="'Apple SD Gothic Neo', 'Noto Sans KR', 'Malgun Gothic', sans-serif"`.
- 상자 너비는 한글 한 글자를 글자 크기만큼, 영문과 숫자를 글자 크기의 0.6배쯤으로 잡고, 렌더해서 넘치는지 본다.
- 화살촉은 `<defs><marker>`로 만들고 같은 파일 안의 id로 참조한다.
- `<title>`과 루트의 `aria-label`에 메시지를 쓴다.
- 움직이는 SVG를 만들 때:
  - CSS `@keyframes`로 읽는 순서대로 나타나게 하고, 전체 길이는 몇 초 안으로 한다. 무한 반복은 쓰지 않는다.
  - 끝 장면에 모든 요소가 보여야 한다. 처음에 숨겼다가 나타나는 요소는 `animation-fill-mode: both`(또는 `forwards`)를 둔다.
  - `@media (prefers-reduced-motion: reduce)`에서는 애니메이션을 끄고 모든 요소를 보인다.

## 아티팩트(HTML)

- `artifact-diagramming` skill이 있으면 SVG 손기술은 그것을 따른다. 색은 `currentColor`, 크기는 `viewBox`, `<figure>`와 `<figcaption>`, `role="img"`와 `aria-label`을 쓰고, SVG 안에 `<style>`과 `<script>`를 넣지 않는다.
- Mermaid는 `<pre class="mermaid">`로 넣으면 아티팩트가 그린다.

## 터미널 텍스트 도식

- 칸 수를 맞출 필요가 없는 꼴을 먼저 쓴다: 들여쓴 나무(`├──`, `└──`), 한 줄 흐름(`요청 → 인증 → 처리`), 세로 흐름(`↓`), 마크다운 표.
- 상자를 그려야 하면 한글, 한자, 이모지는 2칸, 영문, 숫자, 공백, 상자 문자는 1칸으로 세어 테두리를 맞춘다. 그린 뒤 `textwidth.py`로 검사한다.
- 한 줄은 80칸 안으로 하고, 코드 블록(```)에 넣어 고정폭으로 보이게 한다.

## 렌더해서 확인하기 (9.4)

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/render.py" <파일> [--dark] [--end] [--reduced-motion]
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/textwidth.py" <텍스트 도식 파일>
```

- `render.py`는 `.svg`, `.html`, `.mmd`(Mermaid 코드), `.md`(첫 번째 mermaid 블록)를 받아, Chrome 계열 브라우저를 화면 없이 띄워 PNG를 만들고 그 경로를 출력한다. Mermaid 문법 오류면 오류를 출력하고 종료 코드 5로 끝난다.
- 브라우저는 샌드박스 안에서 뜨지 않는다(종료 코드 4). 샌드박스가 켜진 세션이면 이 명령을 샌드박스 밖에서 실행한다. 사용자가 이 명령을 샌드박스 예외로 설정해 두었으면 그대로 실행되고, 아니면 샌드박스 밖 실행 승인을 받는다. 브라우저가 없으면(종료 코드 3) 렌더 확인을 건너뛰고 보고에 밝힌다.
- 두 스크립트 모두 `cd`나 다른 명령과 `&&`, `;`, `|`로 묶지 말고, heredoc(`<<`)이나 파이프로 입력을 넘기지 말고, 한 번에 하나씩 단독으로 실행한다. 샌드박스 예외와 권한 규칙은 명령 전체가 패턴과 맞을 때만 적용된다. 텍스트 도식은 Write로 임시 파일에 저장한 뒤 그 경로를 `textwidth.py`에 넘긴다.
- 샌드박스 밖에서는 임시 폴더(`$TMPDIR`)가 샌드박스 안과 다를 수 있다. 입력과 출력은 절대 경로로 넘긴다.
- 만든 PNG를 Read로 열어 잘림, 겹침, 선 교차, 글자 크기, 강조가 먼저 보이는지 본다.
- 어두운 화면에서도 볼 그림(아티팩트, 다크 스타일을 둔 SVG, GitHub 문서)은 `--dark`로 한 번 더 그린다.
- 움직이는 SVG는 `--end`로 끝 장면을, `--reduced-motion`으로 움직임을 끈 장면을 그려 둘 다 모든 요소가 보이는지 본다.
- 문서에 넣을 Mermaid는 코드 블록 내용을 `.mmd` 파일로 저장해서 그린다.
