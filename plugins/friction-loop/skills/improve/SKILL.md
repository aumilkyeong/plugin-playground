# 주간 자가개선 검토

개인 확장 시스템이 스스로 나아지게 하는 루프의 한 바퀴다. 순서는 위치 확인 → 수집 → 묶기 → 제안 → 반영 → 기록이다. **사용자가 번호를 골라 승인하기 전에는 어떤 파일도 바꾸지 않는다.**

검토 기간(일): $ARGUMENTS (비어 있으면 7)

## 0. 위치 확인

현재 작업 폴더에 `.claude-plugin/marketplace.json`과 `plugins/` 폴더가 둘 다 있어야 한다. 하나라도 없으면 아무것도 읽거나 바꾸지 말고, 자가개선 시스템 저장소(마켓플레이스 저장소)로 옮겨서 다시 실행하라고 안내한 뒤 멈춘다.

결정 기록 `docs/decisions.md`는 없어도 된다. 포크 직후처럼 처음 검토하는 저장소이므로, 처리된 마찰이 없는 것으로 보고 계속한다. 파일은 5단계에서 만든다.

## 1. 수집

다음 세 명령을 하나씩 따로 실행한다. 모두 읽기만 한다. 다른 명령과 묶거나 `echo` 구분선을 끼우지 않는다. 묶은 명령은 `python3` 허용 규칙에 맞지 않아 권한 확인이 뜨거나 막힌다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/friction.py" --data "${CLAUDE_PLUGIN_DATA}" list --open --decisions docs/decisions.md
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/recent_prompts.py" --days <검토 기간>
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/recent_signals.py" --days <검토 기간>
```

앞의 둘은 사용자가 말한 것(마찰 기록, 직접 입력한 프롬프트)이다. 마지막은 사용자가 말하지 않은 것, 즉 직접 답한 권한 확인, 권한 거절(사용자·규칙·자동 모드·hook), 도구 오류, 중단이다. 신호마다 도구와 입력이 붙고, `→` 줄은 신호 뒤에 사용자가 처음 한 말이다.

`docs/decisions.md`가 있으면 '주간 지표'와 최근 '변경 기록'도 읽는다. 지난번에 보류하거나 기각한 것을 다시 제안하지 않기 위해서다.

## 2. 묶기

마찰 기록, 프롬프트, 신호에서 원인이 같은 것끼리 묶는다. 특히 다음을 찾는다.

- 같은 지시나 설명을 여러 세션에서 되풀이한 것. 이 묶음 수가 북극성 지표 '반복 지시'다.
- Claude의 결과를 고치라고 한 요청("아니", "다시", "그게 아니라", "말했잖아" 같은 표현).
- 신호의 '반복' 목록: 매번 직접 승인한 명령, 자동 모드나 hook에 거듭 막힌 작업, 같은 명령의 반복 실패. 도구 오류에는 Claude가 곧바로 스스로 바로잡은 사소한 실수도 섞여 있다. 그래서 같은 원인이 여러 세션에서 나왔거나 `→` 줄의 사용자 말로 이어진 것만 묶음으로 삼는다.
- 중단과 거절 바로 뒤의 사용자 말. 무엇이 기대와 달랐는지가 가장 직접 드러난다.

묶음마다 근거(마찰 ID, 날짜와 짧은 프롬프트나 신호 발췌)와 빈도를 남긴다. 한 번만 나온 것은 '근거 약함'으로 표시한다. 발췌는 묶음을 설명할 만큼만 인용하고, 명령에 토큰이나 비밀값처럼 보이는 것이 있으면 가린다.

## 3. 제안

묶음마다 처리 하나를 고른다.

| 처리 | 언제 |
|---|---|
| 만들기 | 이 일을 담을 확장이 아직 없다 |
| 고치기 | 확장은 있는데 발동하지 않거나 결과가 틀린다 |
| 승격 | 지침(CLAUDE.md, 메모리)으로는 지켜지지 않아 더 강한 형태가 필요하다 |
| 지우기 | 쓰이지 않거나 다른 확장과 겹친다 |

담을 형태는 `${CLAUDE_PLUGIN_ROOT}/skills/improve/references/forms.md`의 형태 선택 기준을 따른다. 판단이 갈리면 약한 형태를 고른다.

제안은 다음 열을 가진 표 하나로 보여 준다.

| 번호 | 처리 | 형태와 파일 위치 | 근거(마찰 ID·신호·빈도) | 기대 효과 | 재현 eval 요약 | 상시 컨텍스트 비용 |
|---|---|---|---|---|---|---|

- 상시 컨텍스트 비용은 늘어남, 그대로, 줄어듦 중 하나로 적는다.
- 지우기 후보를 최소 하나는 검토한다. 사용자에게 `/skill-doctor`를 실행해 한 번도 호출되지 않은 skill과 최근 쓰지 않은 플러그인을 함께 보자고 제안한다.
- 직접 승인이 반복된 명령은 허용 규칙 후보다. settings를 바꾸는 일이므로 4단계 규칙대로 바꿀 내용만 보여 준다. 읽기 전용 명령이면 `/fewer-permission-prompts`를 함께 제안한다.
- 묶음이 하나도 없으면 그렇다고 말하고 5단계 '주간 지표'만 기록한다.

표를 보여 준 뒤 어떤 번호를 반영할지 묻고 **여기서 멈춘다.**

## 4. 반영 (승인한 번호만)

- 변경은 이 저장소의 `plugins/` 아래에서만 한다. `~/.claude/`나 다른 프로젝트의 파일은 바꾸지 않는다. CLAUDE.md나 settings를 바꿔야 하는 제안이면 바꿀 내용을 보여 주고 사용자가 직접 적용하게 한다.
- 변경마다 그 마찰을 재현하는 eval 케이스를 해당 플러그인의 `evals/`에 추가한다. 형식은 `plugins/friction-loop/evals/README.md`를 따른다.
- 바꾼 플러그인의 `.claude-plugin/plugin.json`에서 `version`을 올린다. 새 확장은 minor, 수정과 삭제는 patch.
- `claude plugin validate --strict <플러그인 경로>`를 실행해 통과시킨다. 실행할 수 없으면 그렇다고 알린다.

## 5. 기록

`docs/decisions.md`를 고친다. 파일이 없으면 `${CLAUDE_PLUGIN_ROOT}/skills/improve/references/decisions-template.md`를 그대로 복사해 만든 뒤 고친다.

- '변경 기록'에 반영한 것, 보류한 것, 기각한 것을 한 줄씩 추가한다. 처리한 마찰 ID를 반드시 적는다. ID가 적힌 마찰은 다음 검토부터 열린 목록에서 빠진다.
- '주간 지표'에 이번 주 행을 추가한다. '신호' 칸에는 `recent_signals.py` 첫 줄의 신호 수를 적는다.

마지막으로 바뀐 것을 한 단락으로 요약하고, 설치 방식에 맞춰 반영하는 법을 안내한다. 어느 방식으로 설치했는지 모르면 두 경우를 모두 보여 준다.

- 이 저장소를 로컬 경로 마켓플레이스로 설치했다면 플러그인이 제자리에서 로드되므로 `/reload-plugins`만 실행하면 된다.
- GitHub 같은 원격 마켓플레이스에서 설치했다면 먼저 변경을 커밋해 push한다. 그 마켓플레이스의 자동 업데이트가 켜져 있으면 다음 세션을 시작할 때 새 버전을 받고, 그 세션에서 `/reload-plugins`를 실행하면 바로 적용된다. 꺼져 있으면 바꾼 플러그인마다 `claude plugin update <플러그인>@<마켓플레이스>`를 실행한 뒤 `/reload-plugins`를 실행한다. 마켓플레이스 이름은 `.claude-plugin/marketplace.json`의 `"name"`이다.
